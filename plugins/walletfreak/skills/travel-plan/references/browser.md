# One browser with opt-in remembered sessions

The plugin supplies one walletfreak-browser MCP connection through scripts/browser.py. It launches pinned @playwright/mcp@0.0.68 with headed Chrome, stdout output and no code generation. The wrapper reads the local settings chosen by the user.

Temporary mode is the default: --isolated, no reusable session after closing. Remembered mode uses a dedicated local browser-profile directory under ~/.walletfreak/local, never the user's normal Chrome profile. Enable it only after the user chooses Remember sign-ins. Mode changes and forget-all take effect on the first browser use after the host restarts its WalletFreak MCP connection; closing a browser tab alone does not restart the wrapper.

One process owns the browser lock. If another Codex/Claude host holds it, ask the user to close that host's WalletFreak connection. Do not delete locks, kill unrelated browsers, attach a personal browser or bypass the wrapper. Saved browser sessions are sensitive authentication material; do not read, export or copy cookies, storage state, passwords or profiles. Do not enable traces, video, secrets files or unrestricted file access.

Account connection requests are handled by the active agent using the already connected browser. Navigate to the catalog's official provider entry point, inspect the empty login form and use the saved-sign-in bridge described in `wallet-sync` when the user requests login or balance refresh; otherwise let the user sign in directly. For redirects to a different login domain, verify it belongs to the provider before user sign-in. Pause while credentials, MFA or CAPTCHA are being entered; never request them in chat or take snapshots of filled login forms. Resume after the user confirms completion, inspect a non-sensitive authenticated view, and record only a generic observation such as "Provider account navigation visible". Do not infer connected status from a browser profile or a successful page load. Redact member names/numbers from saved findings.

Remembered does not mean currently authenticated. Recheck when beginning provider research; session expiry or a verification prompt requires sign-in again. Users can request forgetting ALL local sessions; setup schedules removal on the next wrapper start, while no other wrapper owns the profile. It does not revoke provider-side sessions and does not delete trips or the optional traveler profile.

Information visible to the agent may enter model context and host history. On blocked access, stop retries and accept redacted user-supplied evidence with its observation time. Never bypass site controls. Transactions, enrollment and point transfers remain user-operated in both browser modes.

Sign-ins uses encrypted local JSON with a device-held key. The walletfreak_sign_in bridge fills credentials only on their saved exact HTTPS origin without returning secrets. Never inspect filled credential forms or read raw credential/key files. Older master-password sign-ins require one user-operated unlock to migrate; never ask for that password in the conversation.
