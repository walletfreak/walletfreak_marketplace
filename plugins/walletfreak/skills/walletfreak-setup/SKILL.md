# Setup

WalletFreak Travel contains all provider guides, trip planning, lounges and the one shared local server. WalletFreak Credit Cards adds profile, card-benefit, wallet-optimization and balance-sync skills; Spending and Shopping add their own research skills. Check Python 3.10+, Node.js 18+ and Chrome. Use only the bundled walletfreak-browser connection. Its scripts/browser.py wrapper controls the pinned Playwright server and a dedicated browser profile.

Read [browser/session guidance](../travel-plan/references/browser.md). Open the dashboard by running `python3 <this-plugin>/scripts/local.py start`, resolving the plugin root from this skill's installed path. Return the printed private localhost link to the user; the fragment is a local access key, so never include it in public artifacts. On a fresh workspace, the dashboard offers wallet details and optional connected accounts. Travel uses the bundled Concierge layout without a layout picker. Existing saved data is not replaced. Opening setup alone does not trigger financial intake or provider sign-in. Always run start again before sharing a viewer link, especially after a plugin update; it replaces a server from an older installation without deleting saved data. Use the newly printed link because a restart changes its access key. If start fails, report the error instead of returning a cached link.

Show the routed Home, Travel, Wallet, Spending and Shopping views; Plugins & skills is under More. Legacy `/actions`, `/credit-cards` and `/settings/sign-ins` links resolve to Travel or Wallet without deleting data. Travel shows saved trips, a route map when locations are known, its calendar, trip follow-ups and research files. Wallet has separate credit card, airline loyalty, hotel loyalty and card rewards sections. Add a card or loyalty account first, then connect its encrypted sign-in from that item. Each item shows its sign-in status and has a Refresh button when a sign-in is saved. The button queues an account-scoped request in `local.py refresh-requests`; it does not launch an agent turn. Process pending requests during the next active conversation and clear only completed requests. Users can report balances manually. Sign-ins are managed from their items; Wallet data offers bulk sign-in cleanup.

Temporary sign-ins are default. If the user explicitly opts into remembering sign-ins, run `local.py settings --input -` with `{"remember":true}`. To forget saved sessions when requested, run `local.py forget --input -` with `{"confirm":"forget-all-local-sessions"}`. These preferences apply on first browser use after restarting the host's WalletFreak MCP connection. Temporary mode does not erase previously remembered sessions. Never describe the current browser as remembered until its actual mode changes. Wallet stores credentials in encrypted local JSON; the normal flow creates its device key automatically (macOS Keychain on Mac, a private key file on other systems), without a separate master password. Users enter credentials and the exact approved HTTPS login origin directly in the Wallet dialog. Older master-password sign-ins require one unlock followed by Move older sign-ins to device encryption; do not reset them. The optional cryptography dependency is still required. Use `wallet-sync` for agent-assisted login and requested balance refresh. For upcoming airline or hotel bookings, use [travel-plan](../travel-plan/SKILL.md) to review authenticated trips, deduplicate and publish confirmed itinerary items; credentials never appear in tool arguments or results. MFA/CAPTCHA remains user-operated and no SMS reader is installed. Never read raw credential/key files or filled forms. Anyone able to run software as the same OS user may access device-held credentials; local storage is not protection against a compromised device.

For browser-lock errors, close the other WalletFreak connection; never delete lock files or use a personal profile. For port conflicts, local.py start selects an available port and reuses a healthy existing service. For data errors, preserve files, report the exact error and do not reset or overwrite the private directory. `local.py stop` stops the dashboard while retaining trips.

When upgrading from 0.2, install the current walletfreak package first, then replace old category plugins with the current walletfreak-credit-cards package if card research is wanted. Existing local profiles and trip files must be retained. Old provider skill names map to provider-research plus the matching provider reference.

If the wallet appears empty, check whether the default saved traveler-profile.md exists. Offer Load existing wallet: it imports supported tables into an empty wallet while retaining dates, approximate values, ownership notes and the original file. Import is explicit; do not overwrite an existing wallet. The Plugins & skills tab shows only enabled WalletFreak packages from the WalletFreak marketplace in local Codex metadata; it never invokes a skill.

WalletFreak Spending replaces the earlier Finance package and has the spending-analysis skill and bank-specific import guides. Its local ledger uses this same server and existing saved data. Open Spending to drop PDFs/CSVs, copy local references and view agent-published metrics. CSV previews and categories remain in an optional spreadsheet section. Direct import does not send statement content to the agent; do not inspect the private sheet unless requested.

Travel renders the bundled Concierge template with locally bundled components. The layout API remains for legacy data; the fixed personal Travel page renders the bundled template. Use dashboard-builder only when the user explicitly requests a component or template change; the public gallery supplies data-free JSON.
Saved dashboard edits write to the local data directory immediately after Save. Read the relevant wallet, layout or results command again before answering from saved state; the agent's existing conversation context does not update automatically.
